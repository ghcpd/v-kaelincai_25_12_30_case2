# Role & Objective

You are a software engineer tasked with fixing a critical regression bug in a scientific calculator application. Your goal is to identify and fix the bug that was introduced in version 1.1, restore the functionality that worked correctly in version 1.0, create a corrected version, and execute comprehensive validation to ensure all tests pass.

## Background

A scientific calculator has been in stable production for 8 months (v1.0). Recently, a new feature was added to support angle mode for trigonometric functions (v1.1). While the new feature works correctly, it has inadvertently broken the handling of negative numbers in mathematical expressions.

**What's Broken:**
- All mathematical expressions containing negative numbers fail when angle mode is enabled
- Examples of failing expressions:
  - `-5 + 3` (should return -2.0)
  - `2 * (-3)` (should return -6.0)
  - `10 - -5` (should return 15.0)

**What Still Works:**
- All positive number calculations work fine
- The new angle mode feature itself works correctly (e.g., `sin(30)` in degrees)
- When angle mode is disabled (v1.0 behavior), everything works perfectly

**Original Project Structure:**
```
issue_project/
├── src/
│   ├── __init__.py
│   ├── calculator.py
│   └── tokenizer.py
├── tests/
│   ├── __init__.py
│   ├── test_calculator.py
│   └── test_regression.py
├── README.md
└── requirements.txt
```

## Inputs & Context

**Target Workspace:** Create relevant project files under the designated workspace directory.

**Problem:** The v1.1 tokenizer was modified to support angle mode but inadvertently removed the optional leading `-` for numeric literals, causing negative numbers to be incorrectly tokenized as separate operator and number tokens instead of single negative number tokens.

### Step 2: Identify the Root Cause
1. Review the test failures and identify the patterns in failing expressions

3. Locate the tokenizer regex pattern that changed between versions
4. Identify what the v1.1 pattern is missing that v1.0 had
5. Determine how angle mode affects tokenization
6. Understand why the change broke negative number handling

### Step 3: Implement the Fix
1. Create a new directory `issue_project_fixed/` under the designated workspace

6. Verify that the angle mode feature continues to work
