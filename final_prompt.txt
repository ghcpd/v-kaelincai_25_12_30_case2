# Role & Objective

You are a software engineer tasked with fixing a critical regression bug in a scientific calculator application. Your goal is to identify and fix the bug that was introduced in version 1.1 that broke negative number handling, create a corrected version under the designated workspace, and execute comprehensive validation to ensure all 27 tests pass with complete functionality verification.

## Background

A scientific calculator has been in stable production for 8 months (v1.0). Recently, a new feature was added to support angle mode for trigonometric functions (v1.1). While the new feature works correctly, it has inadvertently broken the handling of negative numbers in mathematical expressions.

**What's Broken:**
- All mathematical expressions containing negative numbers fail when angle mode is enabled
- Examples of failing expressions:
  - `-5 + 3` (should return -2.0)
  - `2 * (-3)` (should return -6.0)
  - `10 - -5` (should return 15.0)

**What Still Works:**
- All positive number calculations work fine
- The new angle mode feature itself works correctly (e.g., `sin(30)` in degrees)
- When angle mode is disabled (v1.0 behavior), everything works perfectly

**Original Project Structure:**
```
issue_project/
├── src/
│   ├── __init__.py
│   ├── calculator.py
│   └── tokenizer.py
├── tests/
│   ├── __init__.py
│   ├── test_calculator.py
│   └── test_regression.py
├── README.md
└── requirements.txt
```

**Problem:** The v1.1 tokenizer was modified to support angle mode but inadvertently broke negative number recognition. The issue only manifests when angle mode is enabled, while the original v1.0 behavior (angle mode disabled) still works correctly.
