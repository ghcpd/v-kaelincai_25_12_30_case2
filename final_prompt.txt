# Role & Objective

You are a software engineer tasked with fixing a critical regression bug in a scientific calculator application. Your goal is to identify and fix the bug introduced in version 1.1 that broke negative number handling, then create a corrected version and execute comprehensive validation.

## Background

A scientific calculator has been in stable production for 8 months (v1.0). Recently, a new feature was added to support angle mode for trigonometric functions (v1.1). While the new feature works correctly, it has inadvertently broken the handling of negative numbers in mathematical expressions.

**What's Broken:**
- All mathematical expressions containing negative numbers fail when angle mode is enabled
- Examples of failing expressions:
  - `-5 + 3` (should return -2.0)
  - `2 * (-3)` (should return -6.0)
  - `10 - -5` (should return 15.0)

**What Still Works:**
- All positive number calculations work fine
- The new angle mode feature itself works correctly (e.g., `sin(30)` in degrees)
- When angle mode is disabled (v1.0 behavior), everything works perfectly

## Inputs & Context

**Target Workspace:** Create relevant project files under the designated workspace directory.

**Original Project Structure:**
```
issue_project/
├── src/
│   ├── __init__.py
│   ├── calculator.py
│   └── tokenizer.py
├── tests/
│   ├── __init__.py
│   ├── test_calculator.py
│   └── test_regression.py
├── README.md
└── requirements.txt
```

**Problem:** The v1.1 tokenizer regex pattern was modified to support angle mode but inadvertently removed the optional leading `-` for numeric literals, causing negative numbers to be incorrectly tokenized.

## Step-by-Step Instructions

### Step 1: Investigate the Bug
1. Run the regression tests to identify failing cases: `pytest tests/test_regression.py -v`
2. Examine the tokenizer.py file to understand how expressions are tokenized
3. Compare the v1.0 and v1.1 regex patterns for numeric literals
4. Identify why negative numbers are not being recognized as single tokens
5. Trace through the calculator code to understand the impact

### Step 2: Identify the Root Cause
1. Analyze how the tokenizer patterns differ between versions
2. Locate the exact regex pattern that was changed
3. Understand what the v1.1 pattern is missing
4. Determine what change will fix negative number handling without breaking angle mode

### Step 3: Create Fixed Version
Create a new directory `issue_project_fixed/` under the designated workspace with the corrected code:

```
issue_project_fixed/
├── src/
│   ├── __init__.py
│   ├── calculator.py
│   └── tokenizer.py      # FIXED VERSION
├── tests/
│   ├── __init__.py
│   ├── test_calculator.py
│   └── test_regression.py
├── README.md
├── FIXES.md              # Document your changes
└── requirements.txt
```

### Step 4: Implement the Fix
1. Copy all source files from the original project to the fixed directory
2. Modify the tokenizer regex pattern to restore negative number support
3. Update the number pattern to include optional leading minus: `r'(-?\d+\.?\d*)|...'`
4. Ensure the fix works for both angle mode ON and OFF
5. Verify that all other functionality remains intact
